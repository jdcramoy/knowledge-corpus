# BSYS-27477 plan — native-file content refresh (Docs/Sheets/Slides) via convert-on-import

Ticket: https://workato.atlassian.net/browse/BSYS-27477 (epic BSYS-27191 Google Drive by Workato MCP Enhancements, Backlog, points 5). NOTE: this plan was drafted and posted to the ticket by a sibling triage worker on 2026-10-09 (comment on the ticket, ending "plan ready — awaiting Josh's authorization"); filed here for the project record. A revised architecture replaced the ticket's original mechanism.

## The mechanism correction (the load-bearing finding)

The ticket proposed Drive `files.update` media upload with convert-on-import. Drive API v3 has no conversion parameter on update; a media PUT stores bytes as-is and does not re-import into a native file. Workato's connector added conversion on the Upload File (create-side) and Export File actions only. The revised plan re-homes the capability on native APIs instead.

## Technical Requirements (revised)

- Slides: excluded — already covered by the GSlides MCP (element/text editing preserves fileId).
- Docs: Docs API `documents.batchUpdate` against the existing fileId (deleteAllContent + insert new body, or structured diff). Preserves fileId, name, location, permissions.
- Sheets: Sheets API `values.update` / `batchUpdate` against the existing spreadsheetId.
- Wiring: sibling action `update_native_file_content` on the custom SDK connector pattern (same approach as the Gmail MCP V3 custom SDK connector), routing by the file's MIME type via the Drive connection's OAuth token. v1 native-file guard stays for unroutable types (e.g. Drawings) with the clear error.
- Content normalization: HTML/plain text for Docs, CSV/TSV/JSON for Sheets.
- Spike gate before the build (1h): a dev test doing a `files.update` media PUT of HTML against a native Doc to prove convert-on-update dead (or adopt the simpler mechanism if undocumented behavior re-imports).

## Acceptance Criteria

- Native Doc refreshes in place; fileId and shareable URL unchanged; same for Sheets.
- Slides path documented as covered by the GSlides MCP.
- Unsupported native types still fail with the v1 clear-error guard.
- Permissions, name, folder unchanged after update.
- Spike result recorded (convert-on-update proven dead or adopted).

## UAT Evidence

Editor test job traces against a real Doc and real Sheet: before/after content read-back, fileId/permissions unchanged, guard error for an unsupported type.

## Risks

- HTML to Docs batchUpdate request conversion is the main build cost; v1 scoped to simple documents (headings, paragraphs, lists).
- Docs/Sheets per-file rate limits need backoff in regeneration loops.

## Points

Ticket shows 5; the sibling plan recommended 3 (SDK action + two native-API paths + guard changes + spike). Reconcile at kickoff.
