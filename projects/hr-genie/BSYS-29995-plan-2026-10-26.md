Goal: generalize the proven one-page freshness sentinel into a full-KB sweep so no stale HR Genie answer survives more than one sweep cycle.

Architecture: one new recipe, MON | HR Genie | KB Freshness Sweep v2, built in dev in the HR Genie project (15643451), scheduled weekly (prod cadence decided at UAT per the ticket). The existing one-page sentinel (82959482) stays as is; this is a sibling, not a rewrite.

Flow:
1. Enumerate. Enterprise Context connector, List documents with advanced filters, data_filters exact match on the source=confluence-hrkb metadata key (the action supports JSON metadata filters, pagination, and an Include metadata toggle that returns the metadata and updated date per document). Explicit high page cap; the regression registry bug taught us default page caps silently truncate at volume.
2. Compare. Foreach over documents in batches of 25: Confluence get page by id, read the version and last-modified. Source newer than the KB doc = drift. Page 404 or deleted = missing. KB doc without the metadata key = anomaly (reported, not failed). Timestamps normalized to one format before comparison.
3. Alert. One consolidated P3 alert through the shared publisher FUNC 76234914, naming the affected pages, capped at the first 20 plus counts so a wide drift produces one alert, not a storm. Clean pass = quiet.
4. Remediation stays as the ticket scopes it: the 82959474 re-ingest webhook per drifted document, manual or follow-on.

Deployment dependency: the v1 sentinel is not in prod yet, that is BSYS-29992's container. v2's prod rollout follows that landing; this build is dev-scoped.

Tests: a seeded stale document (metadata pointed at an old page version) proves the alert fires with the page named; a fresh-KB pass proves quiet. Both authored as dev test cases with the job IDs recorded in UAT evidence.

Risks: Confluence connector rate limits (handled with batch pacing and backoff, no tight loops); metadata key coverage on legacy docs (the anomaly bucket surfaces them rather than failing); KB handle differs dev vs prod (kb-AYc8DXFF vs kb-AYcm4ggH), so the prod deployment needs the handle remap called out in the manifest notes.
