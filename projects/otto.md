## Architecture map (audit 2026-10-08)

**What Otto is:** Slack-first AI agent platform — "a Claude Code coworker that lives in Slack". Agents (persistent, with memory) → Contexts (feature sets: channels, memory, scheduler, events, escalation, sharing, identity) → Sessions (`conv_`/`job_`/`proj_`) → isolated worker pods running Claude Code (gVisor sandbox, bash-sidecar, credential-free worker, centralized anthropic-proxy + egress).

**33 services in services/.** Layers: Edge (otto-ingress, external k8s-manifests repo) → Gateways (app-gateway = SPA/mobile trust boundary; slack-gateway = Bolt Slack app + MCP port; twilio-gateway = SMS/RCS) → Core (api = session lifecycle + internal worker callbacks API; session-bus = Kafka FIFO delivery both directions + 4-tier rate limits; mcp = MCP control plane; scheduler; event-router (Workato PubSub); audit (ClickHouse); billing (Stripe credits); projects; skills (Claude Code plugin sync); notification; feed (skeleton); media-gen; workspace-packages (Workato broker, sole credential holder)) → Sandbox (worker, bash gVisor pod, bash-proxy per-node DaemonSet, egress control plane, anthropic-proxy, efs-controller; sandbox-router lives in external otto-sandbox-platform).

**Key cross-cutting models:**
- Persistence: "execution ephemeral, state durable" — workers hold nothing; sessions resume anywhere via EFS-mounted workspace + claude_session_id lineage (threads fork parent, `/reset` re-forks — docs/slack/session-routing.md is the mechanical trace).
- Identity: Workato Identity service (external) mints user JWTs; `AppLink` rows map external identities (slack_user_id etc.) → `UserEnvironment`; turn-identity tokens assert whose turn it is.
- Acting on behalf of users (docs/escalation.md): `on_behalf_of_user` boolean; mcp proxy resolves current-turn user at call time → policy `allow|ask|block` (`tool_permission` rows, read-only default first, `tool_approval` transient cards) → runs with the user's own OAuth token (`McpUserAuthorization`, encrypted "mcp"). Agent never sees tokens. Cross-user theft structurally impossible.
- Egress v2: bash pods → bash-proxy (per-node, token-stamping, never decrypts) → egress service (verifies session + turn-identity tokens, NetworkRule policy, substitutes `otto-secret:<id>` refs; sole owner of UserSecret). Worker first-party calls go through typed `library/*-client` packages.
- Slack token classes: bot xoxb per SlackInstallation; installer xoxp (identity proof only); per-user xoxp for on-behalf-of search (#1659, stored via services/mcp as signed claims — mcp never holds real Slack creds).

## Key auth-model difference: Workato VUA vs the GWS gateway's first-party OAuth2 (Josh 2026-10-09, SAVE)

- **VUA:** parent/base connection carries the OAuth client + lives in the workspace vault; per-user child runtime connections hang off it; calls execute as the end user THROUGH that chain. The parent is a workspace asset — the source of VUA's documented traps (vault-key plumbing, grant-locked projects, cross-workspace child binding, connection-loss states).
- **GWS gateway design:** "as the end user" is true BY CONSTRUCTION, not configuration. The parent's only job (OAuth client config) is service app-config (.env — not a workspace asset); the children are `mcp_user_authorizations` rows (one first-party grant per user, no vault, no workspace binding); the service resolves the current turn's user from the verified identity claim and returns THAT user's token. No service-account path exists in the registry at all, no bot fallback for the google managed server (unlike slack's) — an identity-less team agent can only act via `on_behalf_of_user` through a real user's grant, or fails closed. The Confluence ruling "never a service account, never an inferred identity" becomes the shape of the system, not a policy.
- One-liner: **VUA made "as the end user" work; this design makes anything else impossible.**
